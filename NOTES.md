## Как запустить

```bash
cd signature-extractor
python -m venv .venv && .venv\Scripts\activate      # Windows (Linux: source .venv/bin/activate)
pip install -r requirements.txt
python main.py [файл ...]                            # файлы из аргументов открываются сразу
python main.py --installer-language en               # только при первом запуске без settings.json
python -m pytest -q tests                            # 151 тест
```

Скриншоты (Linux, Xvfb): `tools/shoot.py <сценарий> <light|dark> <ru|en> out.png [W H]`, пакетно `tools/runall.sh`,
сравнения `tools/cmpall.py` → `compare/<вариант>_<экран>.png` (слева приложение, справа макет без 32 px заголовка окна).
Нужен Tk со шрифтами Xft (взят conda-forge `tk`; Tk из python-build-standalone рисует без Inter и кириллицы).

## Отклонения от макетов и почему
1. **Шрифт**: Inter на Linux вместо Segoe UI Variable; Tk принимает только целые px, поэтому 12,5 → 13 и 13,5 → 14. Отсюда разница ширины текста и редкие другие переносы (21). На Windows используется Segoe UI Variable.
2. **Заголовок окна**: на скриншотах (Xvfb без оконного менеджера) нет системного заголовка, поэтому он обрезан и у макета; у дочерних окон 10 и 21 под Xvfb тоже нет заголовка.
3. **Подсказки**: светлые нативные подсказки Win11, а в макетах 57 и 60 они тёмные (по решению «нативный Win11 важнее»).
4. **Предпросмотр экспорта**: файл = размер графы (решение этапа 3), поэтому подпись заполняет графу, а размерные линии и бейдж показывают размер файла (354 × 118 px · 15,0 мм). В макете показан размер содержимого (246 × 94 px · 10,4 мм).
5. **Поля «Свой размер»**: 64 px, только цифры, с «✓»/«×» (решение этапа 3). В макете 12 поле 88 px с текстом «20 мм» и без «✓».
6. **06/07/09**: в макетах при включённом фильтре тело карточки цвета чернил скрыто, а по спецификации оно видно — сделано по спецификации. На 05 в макете ручной режим, а по умолчанию в приложении «Авто» (на скриншоте 05 включён ручной, как в макете).
7. **Тестовое фото другое**, поэтому авторамка, число штрихов и размеры в мм отличаются от макета по данным, а не по вёрстке.
8. **Тема на скриншотах тёмной темы**: harness ставит «Тёмная» явно, а в макете 27 выбрано «Использовать параметры системы».
9. **Список 35**: ширина списка не меньше 236 (утверждено), а в макете 184.
10. **Движок**: контролы нарисованы на Canvas (PIL, суперсэмплинг), а не стандартными виджетами CTk. Причина: точные радиусы, обводки и состояния Win11, которых CTk не даёт.
11. **«Размеры подписи» в Параметрах** — пока выбор размера по умолчанию; полный менеджер (36/37) — этап 5.
12. **Справка**: вне форматов (start/prep/process/batch) окно собирается из строк `help.<тема>.*` как заглушка; полный центр справки 22–26 — этап 5.
13. **Нумерация** «Сохранить с номером» — «имя (2)», как в ядре этапа 3.

## Изменения по замечаниям (2026-11-17, команда «Вносим изменения»)
Резервная копия дерева до правок: `/workspace/rewrite/_backup_before_remarks_2026-11-17`. Скриншоты: `/workspace/rewrite/remarks_shots`

1. **Тема — без значения в заголовке**: у карточки «Тема» убрано выбранное значение справа, остался только шеврон (как в Калькуляторе).
2. **Порядок вариантов**: Светлая, Тёмная, Использовать параметры системы (`THEME_ORDER` в `settings_page.py`).
3. **Значок темы**: Fluent «Color» (палитра, E790 в Калькуляторе), `ic_fluent_color_20_regular` из fluentui-system-icons (MIT), 1 px; `assets/icons/theme.png`, исходник `svgs/fluent_color_20_regular.svg`.
4. **«Лицензия» в «Сведениях»**: причина — подпись рисовалась на холсте карточки снаружи, а карточка при наведении стирает и перерисовывает холст. Теперь страница передаёт такие элементы через `SCard.extra_draw`, и они перерисовываются вместе с карточкой. Та же ошибка была у разделителей в развёрнутой карточке «Форматы по умолчанию», исправлена так же.
5–6. **Экран 2, инструменты**: по умолчанию ни один инструмент не нажат. Повторное нажатие на активный инструмент выключает его. Клик левой кнопкой вне предпросмотра и вне панели инструментов тоже выключает инструмент. Рамка обрезки видна всегда; ручки и редактирование есть только с «Рамкой области». Без инструмента и с ластиком рамка показана пунктиром без ручек, только для просмотра.
7. **«Поле рамки» во всех режимах**: по умолчанию 0,5 мм (`DEFAULT_MARGIN_MM`). В режимах графы, своего размера и шаблона файл равен графе, а подпись вписывается в графу минус поле. Поле, которое не помещается в графу, не принимается (например, в 15 × 5 поле должно быть меньше 2,5 мм). Почему раньше «не работало» в режиме «Как в исходнике»: размер файла менялся, но предпросмотр вписывал файл целиком и не рисовал его границу, поэтому поле было не видно. Теперь пунктирная граница файла рисуется во всех режимах. Миграция настроек: в v1 значение 2,0 было значением по умолчанию, поэтому при первом запуске оно заменяется на 0,5 (`settings_version` = 2).
8. **SVG без утолщения**: `MIN_STROKE_MM = 0`, контур строится по порогу 50 %, толщина штриха как в исходнике. Функция `thicken_thin_strokes` осталась, но экспорт её не вызывает.
9. **DXF — осевая линия**: в `core/centerline.py` скелет строится так:
   - утончение Zhang–Suen;
   - граф из концов и узлов;
   - короткие отростки обрезаются (длина меньше ≈1,2 толщины штриха);
   - в каждом узле продолжаются две самые прямые ветки, поэтому «X» даёт два штриха;
   - линия сглаживается и упрощается.
   В DXF пишутся открытые LWPOLYLINE с `const_width` = толщине и ближайшим стандартным `lineweight`; `$LWDISPLAY` = 1; HATCH нет. Концы линий продлены на половину толщины, чтобы закрыть стыки. Поле «Толщина линии» стоит в карточке DXF, которая раскрывается шевроном, как карточка PNG. Поле принимает только числа от 0,01 до 5 мм (два знака), с «×» и «✓», по умолчанию 0,18 мм. Значение сохраняется в `settings.json` как `dxf_line_mm`. Новые строки i18n: `export.dxf.line`, `export.dxf.line.desc`, таблица Excel теперь до A1:E301. Предпросмотр вкладки DXF рисует осевую линию в выбранную толщину.
10. **Предпросмотр экспорта**: вместо доли 0,62 × 0,52 рамка вписывается во всю область, за вычетом места под плашку, подпись и размерные линии (`preview_fit`).

## Изменения по замечаниям 11–19 (2026-11-17, вторая партия, «Вносим изменения»)
Резервная копия дерева до правок: `_backup_before_remarks2_2026-11-17/` (и прежний архив `_backup_before_remarks2_2026-11-17.rewrite_code.zip`).

- **11. DXF, средняя линия без ложных перемычек** (`core/centerline.py`):
  - `stitch_edges`: склеивает половины штриха, на которых обход скелета останавливался с «пустым» концом; оставшийся свободный конец рядом с узлом привязывается к нему. Хвостики с пустым концом и крошечные петли внутри узла убираются вместе со шпорами.
  - `resolve_bridges`: короткое ребро между двумя узлами (до 8 × толщины штриха). Если оба штриха входят и выходят вдоль него (в пределах 60°), это пологое пересечение или слияние: штрихи продолжаются сквозь него и перемычка исчезает. «Перекладина» между почти параллельными штрихами отбрасывается, и каждый узел соединяет свои две ветви. Перекладина «Н» не трогается (есть тест). Совсем короткие перемычки (≤ 1,5 × толщины) схлопываются в один узел.
  - `hermite_join`: в сливающемся пятне чернил скелет идёт по середине пятна, а не по штрихам. Поэтому последние ≈ 1,2 × толщины ветвей отрезаются и заменяются кубической кривой Эрмита с касательными ветвей. Пересечение «X» даёт две ровные линии без зазубрины.
