## Цель и платформа

- Приложение **Signature Extractor** / «Извлечение подписи»: Windows-программа, которая из фото или скана подписи делает чистые файлы PNG, SVG и DXF.
- Версия **1.0**, лицензия **GNU GPLv3**, только Windows, не кроссплатформенное.
- Минимум: **Windows 10 версии 1809 (64-bit)** и новее. 32-битные системы не поддерживаются.
- Стек: **Python 3 + CustomTkinter**. Репозиторий: https://github.com/stanislau-salavei/signature-extractor.
- Автор и копирайт в интерфейсе: `© 2026 Stanislau Salavei` (латиница, не ссылка).
- Заголовок окна, ярлык в меню «Пуск» и имя `.exe` следуют языку интерфейса: «Извлечение подписи» / `Signature Extractor`. Номер версии в заголовке окна не показывать.
- Обработка только на компьютере пользователя. В интернет программа обращается исключительно для проверки обновлений, и только если это включено в параметрах.

## Интерфейс и темы

### Общий принцип

- Ориентир — **родные приложения Windows 11**, а не «похоже на Fluent». Макеты v3 уже сверены с ними; если в макете чего-то нет, делай как в эталонном приложении, а не по своему вкусу:
  - страница «Параметры», плотность карточек и тёмная палитра — **Windows Terminal** (Параметры);
  - строки раскрытых карточек, значки строк и полоса прокрутки — **Блокнот** (Параметры);
  - раскрытая карточка «Сведения» и радиокнопки — **Калькулятор**;
  - флажки, выпадающие списки и поля ввода — **Параметры Windows** (Специальные возможности › Контрастные темы; Дисплей › Настраиваемое масштабирование);
  - меню ⋯ — **Диспетчер задач**;
  - зона перетаскивания на экране 1 — **Quick Share**.
- Использовать стандартные виджеты CustomTkinter плюс **один** кастомный: холст предпросмотра. Не опираться на приватные API CustomTkinter (это было условием новой архитектуры, t4s). Элементы, которые CustomTkinter не умеет рисовать как в Windows 11 (радиокнопки, флажки, тумблеры, всплывающие списки, меню), допускается собирать из стандартных виджетов и картинок состояний (см. «Сглаживание»).
- Тема: «Использовать параметры системы», «Светлая», «Тёмная». При системной теме следовать оформлению Windows и обновлять окно, если система сменила тему. При **любой** смене темы, включая переход на системную, перерисовываются **все** элементы: радиокнопки, флажки, тумблеры, поля, списки, меню, фон холстов. Ни один элемент не должен остаться в цветах прежней темы.
- Кнопка ⋯ — утверждённый вариант размера B. Плитки форматов — цветные надписи «PNG» / «SVG» / «DXF», не «ластиковые» значки.
- Дочерние окна (справка по форматам, диалоги, «О программе», «Свой цвет»): локализованный заголовок, без крупной иконки и имени приложения в хроме окна.
- Шрифт: `Segoe UI Variable Text` → `Segoe UI Variable` → `Segoe UI`. Вес 600 — полужирный (Semibold), никогда не 700; если Semibold нет, взять `Segoe UI Semibold`, а при его отсутствии — Bold.

### Заголовок окна

- Как в Windows Terminal: заголовок окна **того же цвета, что фон интерфейса**, а не акцентного цвета Windows. Через `DwmSetWindowAttribute`: `DWMWA_CAPTION_COLOR` (35) = фон окна (`#F3F3F3` светлая / `#202020` тёмная), `DWMWA_TEXT_COLOR` (36) — цвет текста темы, `DWMWA_USE_IMMERSIVE_DARK_MODE` (20) включён в тёмной. Обновлять при смене темы. На Windows 10, где этих атрибутов нет, тихо пропускать.
- В заголовке: иконка 16 × 16, локализованное имя 12 px. Кнопки окна — системные.

### Сглаживание и DPI

- **Все** скруглённые формы и линии рисуются сглаженно при 100 / 125 / 150 %: обводки и углы карточек, флажки, радиокнопки, тумблеры, рамки списков и полей, меню ⋯ и всплывающие окна. Ступенек, «восьмиугольных» колец и квадратных кружков быть не должно. Рекомендуемый способ: рисовать каждое состояние элемента в PIL с запасом 4× (`ImageDraw.rounded_rectangle` / `ellipse`) и уменьшать с `LANCZOS` в `CTkImage` / `PhotoImage`, с кэшем по размеру, теме, состоянию и масштабу; или сглаженные углы самого CustomTkinter.
- Фон под нарисованным элементом совпадает с фоном карточки, на которой он стоит: никаких светлых квадратов вокруг тумблеров, белых углов вокруг меню или серых полос под всплывающими окнами.
- Приложение объявлено **per-monitor DPI aware (v2)**, чтобы Windows не растягивала его как картинку; при переносе окна на монитор с другим масштабом интерфейс пересчитывается и остаётся чётким.

### Клавиши

Утверждено 16.11.2026, сочетания указываются в подсказках кнопок:

- в редакторе на экране 2: **Ctrl+Z** — отмена; **Ctrl+Y** и **Ctrl+Shift+Z** — повтор (в подсказке указан только Ctrl+Y); история **без ограничения шагов**, отдельно для каждого фото;
- **Ctrl+O** — «Открыть файл» (на экранах 2–3 это новая работа, с диалогом 20, если есть несохранённый результат);
- **Ctrl+S** — перейти к шагу «Экспорт», если есть готовый результат;
- **Esc** закрывает окна справки и параметров (не главное окно приложения), а также открытый список или меню;
- **Enter** в текстовом поле применяет значение, как кнопка «✓».

## Файл настроек и что в нём хранить

- Путь: `%APPDATA%\Signature Extractor\settings.json` (обычно `C:\Users\<пользователь>\AppData\Roaming\Signature Extractor\settings.json`). Формат — **JSON**.
- Запись **атомарная**: сначала временный файл в той же папке, затем замена (`os.replace` или эквивалент), чтобы при сбое не оставался обрезанный документ.
- Обновление установщиком и удаление приложения **этот файл не трогают** (свои шаблоны и свои цвета сохраняются и после удаления программы).
- Настройки переживают перезапуск программы.
- Хранить как минимум:
  - тему и язык;
  - «AI-поиск подписи по умолчанию»;
  - «Ускорение на видеокарте»;
  - форматы по умолчанию, размер по умолчанию, «Поле рамки при обрезке» (число в миллиметрах), цвет по умолчанию, разрешение PNG;
  - папку сохранения, шаблон имени, режим «Если файл уже есть»;
  - «Проверять обновления при запуске»;
  - список своих шаблонов размера и своих цветов;
  - последние настройки экспорта, которые должны сохраниться после «Готово» (форматы, размер, разрешение).
- Не заявлять в настройках имя AI-модели и не давать её удалять: модель **встроена** в приложение, пользователь её не скачивает (t34u, t36u).

## Экран 2: инструменты и предпросмотр

- Слева предпросмотр с ползунком «До» / «После». Надписи стоят в нижних углах и **плавно прячутся**, когда разделитель к ним подходит вплотную (t108u). Фон предпросмотра: «Шахматка», «Белый», «Тёмный» — только вид, на файл не влияет. В тёмной теме шахматка тёмная, как на тёмных макетах v3, и остаётся такой (утверждено 16.11.2026): не осветлять и не менять цвет подписи ради контраста.

- Панель инструментов: «Рамка области», «Ластик», «Сбросить к авто»; иконки отмены и повтора с подсказками «Отменить (Ctrl+Z)» / `Undo (Ctrl+Z)` и «Повторить (Ctrl+Y)» / `Redo (Ctrl+Y)`; повтор также по **Ctrl+Shift+Z** (в подсказке указывается только Ctrl+Y). История **без ограничения шагов**, своя для каждого фото. Группа масштаба и «По размеру». На минимуме «Сбросить к авто» и «По размеру» — только иконки с подсказкой (57).
- Рамка (t44s–t45s, справка 24): после распознавания ставится **сама** вокруг найденной подписи; маска строится только внутри неё; пользователь двигает края и углы; «Сбросить к авто» возвращает автоматическую рамку. Если рамка охватывает больше половины листа, нужно подсказать включить «AI-поиск подписи» (это есть в справке 24).

- Ластик: стирает лишние штрихи из результата; действия входят в историю отмены и повтора (Ctrl+Z / Ctrl+Y).
- **Ctrl+O** открывает фото (новая работа на экранах 2–3, с диалогом 20 при несохранённом результате). **Ctrl+S** переходит к шагу «Экспорт», если есть готовый результат; подсказка кнопки «Далее: экспорт (Ctrl+S)».

В справке про толщину писать «на сколько утолщить или утончить линии», не «в миллиметрах».
- Блок «Авто» / «Вручную» и пипетка видны **только когда включён фильтр чернил**.
  - «Авто», цвет успешно отделён (экран **62**, t57u–t58u, t240u): кнопка «Пипетка» скрыта; строка «Цвет чернил: найден автоматически» / `Ink color: detected automatically` и образец найденного цвета. HEX только в подсказке образца, не подписью.

  - «Авто», цвет чернил нельзя отделить от печатного текста (утверждено 16.11.2026, **макета нет**): вместо строки «найден автоматически» показывается серая строка «Цвет чернил не отличается от текста — уберите лишнее ластиком или рамкой» / `Ink color matches the text — remove extras with the eraser or crop frame`; кнопка «Пипетка» **снова видна**; это не ошибка и **не блокирует** переход к экспорту. Текст также есть в справке 24 и в таблице i18n.
  - «Вручную» (05, 08): кнопка «Пипетка» и образец; пользователь щёлкает по линии подписи на предпросмотре. Из успешного «Авто» (пипетка скрыта) в ручной режим переключаются пунктом «Вручную».
- AI-поиск подписи: по умолчанию **выключен**; в параметрах подпись «Включать для каждого нового фото». Модель **IS-Net** (как в rembg) **встроена** в дистрибутив, пользователь её не скачивает, в UI имя модели не показывается (t34u, t36u). Запуск: **ONNX Runtime + DirectML** (t36u). Для пользователя в справке: «На видеокартах с поддержкой DirectX 12 процесс идёт быстрее, в ином случае обработка выполняется на процессоре». Если DirectX 12 недоступен, тумблер «Ускорение на видеокарте» в параметрах **неактивен**, под ним серая строка «Видеокарта не поддерживает DirectX 12, используется процессор» (подробнее — этап 5). Если во время работы ускорение на видеокарте сбоит, для этого фото **молча** переходить на CPU, без диалога. AI нужен для сложного фона, угла, цветной бумаги, печати и лишних объектов; работает медленнее обычной обработки.

## Крайние случаи

- Вставка из буфера не изображением — без падения, понятная ошибка.
- Несколько файлов, среди которых есть не-фото и файлы > 50 МБ: каждое правило применяется независимо (диалог 04 и/или панели 45/46; 46 — на этапе 4).
- Смена файла через ⋯ на экране 2 при несохранённом результате — только через диалог 20.
- Выключение фильтра чернил прячет блок «Авто/Вручную».
- Если в «Авто» цвет не отделяется от текста, строка серая, «Пипетка» видна, «Далее: экспорт» остаётся доступным (для одиночного файла).

- Сбой DirectML в рантайме не роняет приложение: это фото досчитывается на CPU.

## Размер подписи

- Общая карточка над форматами (не трижды в каждом формате). На экране 3 — **ComboBox в стиле Windows 11**, всегда одной высоты. Список раскрывается **поверх поля**, как все списки (35, 58): выбранный размер стоит на месте поля, окно сдвигается, чтобы не выйти за окно приложения, ширина не меньше 236 px, высота не больше 392 px, дальше прокрутка тонкой полосой. Прежнее правило «список размеров открывается вниз под полем» отменено.
- Порядок пунктов: «Как в исходнике», «15 × 5 мм», затем свои шаблоны, разделитель, внизу «Свой размер…». При длинном списке — прокрутка (58). Меню «…» **в этом списке нет**: переименовать, удалить и «Сделать по умолчанию» — только в Параметры › Экспорт › «Размеры подписи» (этап 5).
- «15 × 5 мм» / `15 × 5 mm` — **умолчание для всех языков**, включая английский (t189u). Подпись пропорционально вписывается в рамку 15 × 5 мм с внутренним отступом **0,5 мм** (занимает не больше 14 × 4 мм), пропорции не искажаются, линии не растягиваются (схема t53s–t55u, название ГОСТ в UI нет). В предпросмотре — контур графы, подпись «Графа «Подп.» 15 × 5 мм» / английский текст из таблицы.
- «Как в исходнике»: физический размер в **миллиметрах** берётся по DPI снимка; если DPI в файле нет — считается для **300 DPI**. Под ComboBox (одиночный, 48) тогда показывается серая строка «В фото нет данных о DPI, размер рассчитан для 300 DPI», экспорт **не блокируется**. Разрешение PNG 150 / 300 / 600 меняет **только плотность пикселей**, миллиметры сохраняются. Пример: 128,2 мм дают **1514 px при 300 DPI** (как на макетах 48 и 63), **3028 px при 600 DPI**, **757 px при 150 DPI**. Предпросмотр должен следовать выбранному разрешению PNG: при умолчании 600 DPI на том же фото будет «3028 px · 128,2 мм при 600 DPI», а не подпись с макета для 300 DPI.
- «Свой размер…»: под полем появляются «Ширина» и «Высота» **в одну строку** и ссылка «Сохранить как шаблон» (12, 33). Ссылка открывает 34 «Сохранить шаблон» с полем «Название» (подставляется, например, «20 × 8 мм»).
- Свои шаблоны появляются в списке сразу после «15 × 5 мм». Встроенные «Как в исходнике» и «15 × 5 мм» удалить нельзя. Если удалили свой шаблон, который стоял по умолчанию, умолчанием снова становится «15 × 5 мм».

## Цвет подписи

- Карточка раскрывается шевроном; в свёрнутом виде — образец и имя (на 11 — «Синий»).
- Встроенные кружки, слева направо (t28u, t216u–t217u): «Как на фото» (значок пипетки, цвет чернил со снимка), «Чёрный» `#000000`, «Синий» `#1B2A8A` (умолчание), «Чернильный синий» `#0B1F5C`, «Яркий синий» `#1D3FBF`. Затем кнопка «+» с пунктирной рамкой, подсказка «Свой цвет».
- Названия встроенных и своих цветов — только в подсказке при наведении (60). В тёмной теме у кружков тонкая светлая обводка; сами цвета чернил не осветлять (t224u).
- «+» открывает окно 10 «Свой цвет»: превью на бумаге и на прозрачном фоне, оттенок, HEX, поля R/G/B, «Название», «Отмена» и «Добавить». Добавленный цвет встаёт следующим кружком и **сохраняется между запусками**.
- Добавленный цвет можно удалить **правым кликом**, пункт «Удалить» (61). У встроенных меню нет. То же действие должно быть в параметрах, в «Цвет подписи по умолчанию» (макета раскрытого состояния нет, поведение утверждено в t216s–t217u). Если удалили цвет, стоявший по умолчанию, умолчанием становится «Синий».

## Форматы

- По умолчанию включены **PNG и DXF**, SVG выключен (как на 11 и в параметрах «Форматы по умолчанию»: «PNG, DXF»).
- PNG — карточка с шевроном (59): «Разрешение» 150 / 300 / 600 DPI, в параметрах умолчание **600 DPI**; «Поле рамки» (тот же параметр, что «Поле рамки при обрезке», умолчание 2). Строка «Поле рамки» как на 59 v3: слева подпись 13 px и под ней серая строка 12 px «Отступ от подписи до края файла в миллиметрах» (ключ `settings.margin.desc`); справа Win11 TextBox шириной 64 **только с числом** (без «мм») и через 8 px кнопка «✓» 36 × 32 с подсказкой «Применить» / `Apply` («×» в поле — «Очистить» / `Clear`); Enter тоже применяет. Высота строки не меньше 44.
- SVG и DXF — только переключатель, **без шеврона и без внутренних настроек**. Подписи карточек как на 11: «Растровое изображение для Word и PDF»; «Вектор для веба и графических редакторов»; «Для AutoCAD и КОМПАС, контуры в мм» / `outlines in mm`.
- Вкладки предпросмотра есть **только у включённых** форматов. Предпросмотр показывает то, что уйдёт в файл (пиксели, мм, оценка размера).
- PNG: прозрачный фон, физический размер в мм, число пикселей по выбранному DPI. **Мягкие сглаженные края (антиалиасинг, альфа) только в PNG.**
- SVG: векторизация через Python-порт potrace — библиотека **`potracer` (GPL, совместима с GPLv3 приложения)**. Один проход по маске подписи, порог **50 %**; сплошные контуры выбранным цветом подписи, **без альфы**. Размер в миллиметрах (`width`/`height` в mm) **и** `viewBox`, чтобы размер одинаково читался в Word, Inkscape, браузерах (t54s–t55u). DPI SVG не нужен. Не делать второй проход, из-за которого трассировался фон (ревью t0s).
- DXF: библиотека **ezdxf** (MIT), формат **DXF R2010**, единицы — миллиметры, вставка в CAD в масштабе 1:1. Подпись записывается **закрытыми полилиниями** и **сплошной заливкой HATCH**. Полилинии аппроксимируют кривые potrace с шагом хорды ≈ 0,05 мм. Сущностей **SPLINE** в файле нет. Пустых сущностей не оставлять. Подпись карточки: «Для AutoCAD и КОМПАС, контуры в мм» / `For AutoCAD and KOMPAS-3D, outlines in mm`; в справке 21 и 26: «Подпись сохраняется контурами, единицы — миллиметры.»
- Минимальная толщина штриха **0,18 мм**: если после масштаба штрих тоньше, в **SVG и DXF** его утолщают до 0,18 мм. **PNG не меняется**. Отдельной настройки нет.
- Слева внизу информационная карточка «Какой формат выбрать» и ссылка «Справка по форматам экспорта» — открывает **небольшое прокручиваемое** дочернее окно 21. Длина ползунка пропорциональна тексту (t218u–t219u). Полная справка — этап 5, но текст 21 уже должен совпадать с таблицей и с разделом 26.

## Сохранение (одиночное)

- На этот экран ведёт «Далее: экспорт» и клавиша **Ctrl+S** (если результат уже готов). Кнопка «Сохранить ({n} файл / файла / файлов)» по числу включённых форматов.

Если выбрано несколько форматов, пользователь задаёт **базовое имя**, рядом пишутся `{имя}.png`, `{имя}.svg`, `{имя}.dxf` — не три окна подряд.
- Папка по умолчанию: `Документы\Подписи` или `Documents\Signatures` (имя папки — из таблицы, уже существующую папку пользователя не переименовывать).

# Этап 6. Установщик и релиз

Сначала прочитай и соблюдай `stage_0_common.md`. Этапы 1–5 должны быть приняты, приложение собирается в распространяемый вид. Работа — в ветке `stage-6` и отдельном PR. Коммит и публикация релиза — только по команде пользователя.

## Цель

Per-user установщик Inno Setup без прав администратора, ярлыки, запись в «Установленные приложения», публикация GitHub Release с установщиком и SHA-256, чтобы встроенная проверка обновлений из этапа 5 работала.

## Экраны

Отдельных макетов установщика нет. Имя, иконка и лицензия должны совпадать с приложением. Иконка: `/workspace/mockups/final/icon/app.ico`.

## Сборка приложения

- Приложение упаковывается **PyInstaller в режиме onedir** (папка с exe и зависимостями, не один огромный файл).
- Эту папку Inno Setup упаковывает в установщик с именем **`SignatureExtractor-1.0-setup.exe`** (для следующих версий — `SignatureExtractor-<ver>-setup.exe`).
- Подпись кода (Authenticode) **не делаем в 1.0**; она остаётся необязательной на будущее.
- В рантайме нет сетевых зависимостей сверх проверки обновлений.

## Установщик

- Технология: **Inno Setup**.
- Только **для текущего пользователя**, без запроса прав администратора и без окна UAC — и при первой установке, и при обновлении.
- Каталог установки: `%LOCALAPPDATA%\Programs\Signature Extractor` (обычно `C:\Users\<пользователь>\AppData\Local\Programs\Signature Extractor`).
- Ярлык в меню «Пуск» создаётся **всегда**. Подпись ярлыка следует языку: «Извлечение подписи» / `Signature Extractor`.
- Ярлык на рабочем столе — **по галочке, которая по умолчанию снята**.
- Приложение появляется в списке «Установленные приложения» (Параметры Windows), оттуда его можно удалить.
- Установщик **отказывается** работать на системе старше Windows 10 1809 и на 32-bit, с понятным сообщением.
- Языки установщика: **русский и английский**. При старте выбирается язык Windows; если его нет среди этих двух — **английский**. Язык, на котором прошла установка, становится **начальным языком интерфейса приложения** при первом запуске; позже его можно сменить в параметрах.
- Передача языка в приложение (утверждено 16.11.2026) — **только аргументом запуска** `--installer-language ru|en` через точку входа из этапа 1 (`read_installer_language()`). Файл `installer_language.txt` установщик **не создаёт**, переменных окружения не задаёт. Аргумент передаётся при запуске программы в конце установки; чтобы язык подхватился и при первом запуске из «Пуска», тот же аргумент записан в параметры ярлыков (в «Пуск» и на рабочем столе). Приложение учитывает его только при первом запуске без `settings.json`, поэтому дальше и после обновления поверх язык пользователя не меняется.
- Обновление ставится **поверх** прежней версии в тот же каталог. Если приложение запущено, установщик **просит его закрыть**. Файл `%APPDATA%\Signature Extractor\settings.json` при обновлении и при удалении **не трогать**.
- В дистрибутив входят: сборка onedir, встроенная модель IS-Net, текст GNU GPLv3, иконка, таблица строк (или уже упакованные ресурсы).
- SHA-256 установщика **считается при сборке** и публикуется вместе с ним (см. ниже).

## Релиз на GitHub

- Репозиторий: https://github.com/stanislau-salavei/signature-extractor.
- Публикация — **только по команде пользователя**. Тег вида `v1.0.0`; версия приложения **1.0**.
- В файлах релиза рядом: `SignatureExtractor-<ver>-setup.exe` и **`SignatureExtractor-<ver>-setup.exe.sha256`**. Та же контрольная сумма дублируется в тексте заметок релиза. Приложение на этапе 5 скачивает оба и сверяет сумму до запуска установщика.
- Описание релиза понадобится ссылке «Заметки о выпуске». Не выдумывай текст заметок без пользователя.
- После публикации «Проверить сейчас» в сборке 1.0 не должен предлагать обновление на саму себя; при следующем теге — должен показать диалог 32, скачать установщик, сверить SHA-256, при несовпадении показать ошибку и удалить файл, при совпадении запустить установщик без UAC и открыть новую версию.
